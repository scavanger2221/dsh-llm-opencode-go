# ADR 0003：按模型覆盖项只声明它改动的部分

[English](0003-per-model-overrides-that-state-only-what-changes.md) | 中文

## 状态

已接受 —— 2026-09-25

## 背景

卡片原来的模型分区是「手写覆盖项」的编辑器。它一开始是空的 ——「没有覆盖项 — 直接使用内置目录。」—— 添加一条意味着输入一个用户必须事先知道的模型 ID，或打开另一处 ID 芯片列表去挑一个。结果就是这个设置界面**看起来**完全没有按模型的设置，这正是它被反馈的方式：「there is no individual model setting on the plugin」。

有三件事决定了按模型编辑器能做成什么样：

- **`LlmDiscoveredModel` 就是发现接口的全部契约。** Host 通过 `llm.registerModelDiscovery` 回答 `id`、`name?`、`contextWindow?`、`maxTokens?`、`inputModalities?`；服务会把返回值规范化为恰好这些键。**协议**与**推理开关**不在其中，任何配置界面都无法读回一个不是自己声明的模型的这两项。
- **目录合并只取覆盖项声明的内容。** `mergeModel` 展开已装条目并应用条目携带的字段，因此只写一个字段的条目只改一个字段。
- **旧编辑器会声明每个字段。** `canonicalModel` 总是写出 `api`、`reasoning` 与 `input`，协议默认取 `openai-completions`。

三者合起来就是一个陷阱：必须写出自己读不到的协议的表单只能靠猜，而 `mergeModel` 会照用这个猜测 —— 修改某个模型的上下文窗口会悄悄把它从 Anthropic Messages 换到 Chat Completions。

另一处配置界面是该行在 profile patch 中的 `config:` 段；而在 0.1.7 上已经没有 `settings.yaml` 可以退回：Harness 把它一次性导入为 `settings.yaml.imported` 后就不再读取。

## 决定

把模型分区改成针对**实际生效目录**的按模型编辑器，并让覆盖项只声明它改动的部分。

- Host 半边用自己掌握的模型发现事实作答：每个目录模型的 `name`、`contextWindow`、`maxTokens` 与 `inputModalities`，并且通过实时目录解析（因此已存的覆盖项会体现在返回值里）。
- `lib/client.js` 为该路由提供的每个模型渲染一行 —— 先按目录顺序列出目录中的模型，再列出目录未提供、但有覆盖项的 id —— 并显示请求会实际使用的值：覆盖项声明了的用它，其余用目录的。带覆盖项的行会被标记，移除它即把该模型交还目录。
- 编辑器的每个字段都从**继承（Inherit）**开始，`canonicalModel` 会把继承的字段排除在条目之外。`modelDraftOf` 把缺失字段映射回继承，因此已存条目可原样往返。
- 只有当模型由本插件自己的目录描述时，才可以继承协议。按 ID 添加的模型不在其中 —— Host 会用同协议模板合成它 —— 因此该覆盖项必须显式指定协议。
- 覆盖项按字段逐一比较，而不是用 `JSON.stringify`，因此手工编辑的 patch 若只是键顺序不同，不会被当成改动而暂存重写。
- 条目还可以携带 `disabled: true`，卡片把它呈现为每行的**停用**按钮。此时目录会保留该 id 的**描述**但不**提供**它：`models()`、`ids()` 与 `get()` 都会跳过它（提供方不再宣告它、选择器不再提供它，指名它的请求会直接失败并说明该模型已停用），而 `all()` 仍会给出它，模型发现也以 `all()` 作答，因此卡片仍能渲染该行（连同各项事实）以便重新启用。目录刷新绝不会把已停用的 id 加回来，因为配置声明的 id 属于配置而非端点。停用只写入这一个标记；当条目只带这一个标记时，启用会直接删除它。
- 卡片对所有暂存内容仍只有一个 Save；按模型表单只暂存列表中的一条。

## 后果

- 修改某个模型的一项事实不再重写其它项。卡片测试固定了这一点：协议留在继承状态的模型，其写入不含 `api` 键；适配器测试固定了部分覆盖项会保留已装协议、推理开关与模态。
- 列表的信息量取决于模型发现。发现无法描述的模型 —— 端点提供、但固定目录与 models.dev 都不认识的 —— 会显示其 ID 与未知事实，直到用户自行声明；容量绝不会被臆造。
- 模型的协议与推理开关只有在覆盖项声明它们时才显示在列表里，因为发现契约没有对应字段。要拓宽该契约属于 Harness 的改动，而非本插件。
- 若某个会话或 `agent-default-model` 仍指名已停用的模型，请求会直接失败而不会被发出。这正是本意，但也意味着停用你当前正在对话的模型会让下一次请求失败，直到另选一个模型。
- 卡片文案随界面更新：该分区改名为「模型」（原为「你的模型」），并在提供继承选择的地方解释继承。
